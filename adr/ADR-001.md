# ADR-001: Stack tecnológico general

## Estado
Aceptado

## Contexto
Necesitamos una aplicación de facturación VERI*FACTU de escritorio para Linux y Windows. El proyecto .NET (Avalonia) ya existe y es funcional. Se nos pide clonar su funcionalidad usando Harbour.

## Decisión
El stack tecnológico general y aprobado del proyecto es:

- Harbour como lenguaje, compilador y runtime.
- HWGUI como interfaz de escritorio, con WinAPI en Windows y GTK3 en Linux.
- SQLite mediante `hbsqlit3` como base de datos local.
- `hbcurl` para HTTP/SOAP, HTTPS y certificado cliente.
- `hbhpdf` para generar facturas y listados PDF.
- `hbzebra` para generar códigos QR.

Estas tecnologías constituyen la base del producto. Cualquier sustitución requiere una ADR posterior que justifique el cambio, su impacto en Linux y Windows, y el plan de migración.

## Consecuencias
Positivas:
- Código xBase único para Windows y Linux (HWGUI abstrae la diferencia)
- Integraciones fiscales y documentales resueltas dentro del ecosistema Harbour
- Base de datos local sin necesidad de servidor
- Comunidad Harbour activa desde 1999

Negativas:
- Sin async/await — las llamadas SOAP a AEAT bloquean la UI
- Sin MVVM con binding reactivo — eventos directos de ventana
- La superficie común de HWGUI debe validarse en Linux y Windows
- El paquete Linux debe incluir o declarar sus dependencias nativas
